# Decisions of both owners

One line per decision, newest at the bottom. A decision that changes an earlier one says so.

- **2026-10-25 · Repository.** Private GitHub repository `szlcx404/amiricord`, shared with Neversleeper. Both are authors and owners; the licence stays GPL-3.0-or-later until both agree otherwise.
- **2026-10-25 · Areas.** Neversleeper starts with the **Plugins tab**; szlcx404 works on **Privacy & Security** (see `docs/collaboration.md`).
- **2026-10-25 · Logs.** Each owner keeps their own log on their own PC (`CONTEXTO-<github user>.md`, not published). Decisions for both go here.
- **2026-10-25 · Joining work.** Branches `<github user>/<topic>`; Claude brings `main` in, resolves conflicts, runs the checks and joins the work after the owner's OK (see `CLAUDE.md`).
- **2026-10-28 · Fewer working rules.** `CLAUDE.md` no longer asks for an analysis note before the work, tiers of care, a mutation check or a commit plan. Analysis, designs and reports are written only when the owner asks for them, and a plugin is analysed only when the owner says so. The safety and privacy rules, the checks, branches and joining work are unchanged. `CLAUDE.md` is the single place for the rules.
- **2026-10-27 · No approval of the other owner first.** Either owner may change the shared core files and bring in plugins from other projects without asking the other first; what was touched is said in the commit message and the pull request. This replaces "told to the other owner before it is joined" and "needs both owners' decision" (the line below of 2026-10-25 about choosing plugins together). Credits and licence headers for adapted code are still required. szlcx404 told Claude that Neversleeper gave her permission; Claude did not see her answer.
- **2026-10-25 · TestCord plugins.** szlcx404 first asked to add all TestCord plugins switched off, then decided **not to add them all**. Plugins from other projects come in one by one, chosen by the owners, each with its credits and licence header, and only after the build loads code of plugins that are off only when they are switched on (today every plugin's code is bundled into `renderer.js`).
- **2026-10-28 · Name.** Neversleeper uses the GitHub name **Neversleeper**; the name is used everywhere in the project.
- **2026-10-28 · Updater.** Both owners agree to an updater: a "Check for updates" button in a new tab of the Amiricord settings, and an "Update now" button when a newer version exists. It is the one exception to "no network except Discord": it only talks to the project's GitHub releases, only when the person presses the button, and checks the SHA-256 of every file before installing (no signing keys; the owners' GitHub accounts have two-step login). The short descriptions of each version are kept in a news file written by Claude. Neversleeper confirmed it; szlcx404's agreement was reported by her, Claude did not see it. Built the same day (`src/main/updater.ts`, the Updates tab, `NEWS.json`, `pnpm release`); the privacy-design rule in `CLAUDE.md` now names this exception. The repository must be public for other people to read the releases.
- **2026-10-28 · Registry of Amiricord users.** Neversleeper (project owner) decided that the "Amiricord User" badge must not depend on a character in the pronouns (it is lost when someone edits or clears them, and it does not fit when they are at Discord's limit of 40 characters): everyone who runs Amiricord is added automatically to a list and gets the badge. szlcx404 had already agreed that each Amiricord may send the id of its own account to something of the project. How: a Cloudflare Worker (free plan, `worker/`, deployed at `https://amiricord-registry.amiricord.workers.dev`) keeps the ids in a KV store; the Badges plugin sends `POST /register {"id"}` once per start (main process, declared host, nothing else is sent) and reads `GET /users` (one id per line) every two hours. No GitHub token exists anywhere: the Worker serves the list itself, so a client never needs to write to the repository (a client cannot keep a secret). The list is public by design. The ids are not checked against Discord (nothing can prove who sends one): anybody can register another person's id and the only effect is that account showing the badge. Limits (free plan, from memory): about 100 000 requests a day, about 1 000 new ids a day; at one list read per client every two hours that is enough for several thousand people, and the list can later move to a file in the repository if it grows. The invisible mark in the pronouns stays as a second way (kept written back every five minutes) and is the only way until the registry has been read. Not seen yet: registering and the badge drawn from the list in a real Discord.
- **2026-10-29 · Badges.** Neversleeper (Neversleeper) decided, after reading how TestCord does it (`docs/analysis-03-badges.md`): (1) an "Amiricord Owner" badge for the two owners and the badges the owners hand out through a list, `badges/badges.json`, kept in this repository and read by every Amiricord from the `main` branch at start and every 30 minutes (only by the main process, only that host, `raw.githubusercontent.com`), managed with `pnpm badges` (no Discord bot: a bot would need a token and a computer left on); (2) an "Amiricord User" badge for everyone, drawn when a profile's pronouns end with an invisible mark that the plugin writes to the person's own profile, ALWAYS ON: the plugin is core and has no switch, because the point is to know who uses the program (Neversleeper, the same day, after the first version had two switches). This overrides two earlier rules: "no network except Discord" (now two exceptions, the Updates tab and this plugin; this one is automatic, not a button) and "no automatic writes to the account" (`docs/analysis-02-privacy.md`, rule 2). What is left of the safeguards: the card shows "High risk: writes to your account" and the description says what it does; the mark is an invisible two-character ending of the pronouns and nothing else is written; it is not TestCord's, so the two mods do not mix. NOT possible any more: a person cannot stop it from Amiricord, and the mark stays in their pronouns after Amiricord is removed (they can delete it by editing their pronouns; it cannot be seen). Safe mode also runs it, because core plugins do. Same day: its card is drawn in the Plugins tab only for the owners (`OWNER_ONLY_PLUGINS` in `src/shared/project.ts`, checked against the Discord id of the account in use); the badges and the mark work for everybody. The Privacy & Security tab still lists the plugin with its network and account permissions, so the program does not hide what it does there. szlcx404's agreement was NOT seen: ask him before this reaches other people (it is on `main` only if it was pushed). Built 2026-10-29 in `src/plugins/Badges`, `src/shared/badgeList.ts`, `scripts/badges.ts`.
- **2026-10-29 · Developer tools on by default.** Both owners decided that Discord's developer tools and the console are switched on for everyone who installs Amiricord, so neither owner has to do it by hand any more. `pnpm inject`, `pnpm repair` (Discord closed) and the engine at every start of Discord (before Discord's own code runs, so people who only use the Updates tab get it too) set two things in Discord's own data folder: the flag `DANGEROUS_ENABLE_DEVTOOLS_ONLY_ENABLE_IF_YOU_KNOW_WHAT_YOURE_DOING` in `settings.json`, and the developer tools' saved choice `disable-self-xss-warning` ("allow pasting") in `Preferences`. Known cost, accepted by the owners: the console's warning against pasting code is off, so someone who is told to paste a script into the console can lose their account. Uninject leaves both as they are. This changes the line in `nativeWindow.ts` that said Amiricord does not touch that file.
- **2026-10-29 · BetterDiscord plugins and the developer-tools shortcut.** Neversleeper asked for support for BetterDiscord plugins (`.plugin.js`), written by us from scratch (no code of another mod; the code mentions none). How: the plugin `BetterDiscord` (`src/plugins/BetterDiscord`) is a **core plugin (always on, no switch; Neversleeper, the same day, so that nobody has to look for it in the list)** and declares `permissions.code.dynamic`, because it runs the text of a plugin file as code (`new Function`, only in `runner.ts`); its card shows the risk and says it runs without Amiricord's permission limits. The only BetterDiscord code that can ever run is the files of `src/betterdiscordplugins/*.plugin.js`, which the build puts inside `renderer.js` (nothing is read from the disk or downloaded at run time; to add a plugin the owners put the file there and build). The layer runs nothing by itself: each BetterDiscord plugin has its own switch, off by default, kept in the layer's own storage; the list of plugins that are on survives restarts. `BdApi` is made per plugin so everything a plugin adds (patches, styles, watchers, tooltips) is taken away when it stops. Done: Patcher, Data (synchronous, saved to storage), DOM, Logger, Webpack (filters and `getModule` over the modules that already ran: Discord's bundler gives no module cache, so the engine hands the list to plugins that declare dynamic code, `ctx.modules`; modules that give out the token are never offered), UI (toast, alert, confirmation, tooltip, settings panel builder), Utils, ReactUtils, Hooks, Plugins, Net.fetch, the old names. NOT done (a call does nothing and says so once): ContextMenu.patch/buildMenu, Commands, Themes, plugins that need Node modules (`fs`, `electron`; they fail with a clear message) or a library such as ZeresPluginLibrary or BDFDB. No third-party BetterDiscord plugin is shipped: the three that another mod bundles have licences we have not checked; only our own `AmiricordSample` is. Same day: plugin `DevToolsShortcut` (F12 and Ctrl+Shift+I open Discord's developer tools through the main process; on by default; it takes the key so Discord's own toggle does not fire too). Neither was tried in a real Discord at the time of writing; only tests with fakes.

- **2026-10-29 · ProfileCopyButton findings, and the third slice (LastActive, PendingFriendRequest, UniversalMention, FriendTags, Ghosted, Experiments).** Found in her Discord (build 653945): (1) the REST object is found with `byProps("get","post","put","patch","del","!Request","!getXHR")`, otherwise the finder returns superagent (DeleteMe had the same bug and its test was updated); (2) a custom status is NOT saved by `PATCH /users/@me/settings` (it answers OK and changes nothing): it is `PATCH /users/@me/settings-proto/1` with the protobuf `status(11).customStatus(2)`, written with every field, plus a local `USER_SETTINGS_PROTO_UPDATE` (`partial`, `local`) so the client shows it; its emoji must be one the person can use, so it is uploaded to one of their servers like the bio's emojis (`uploadEmoji` reuses one with the same name); (3) the server tag goes into the editor as `pendingPrimaryGuildId`, but Discord does not offer a server in its list while the person is a pending member of it (`isPending`, flag 8; seen with one server that asks to complete its onboarding): the plugin now takes the person to the server and sets the tag by itself when they finish; navigation is Discord's own function found by `byCode("transitionTo - Transitioning to")` (the module has no readable names), which LastActive uses too; (4) joining through a tag card is `PUT /guilds/{id}/members/@me?lurker=false`, which shows a captcha that only a human can solve and Discord retries by itself. Stores must not be taken with `.get()` inside `start()` (Discord has not loaded them yet and the finder reports a miss): keep the finder and ask when used. HomeTyping, MicLoopbackTester and the six new plugins were changed to that. New: LastActive, PendingFriendRequest (only the right-click entry; the original's patches use translation keys), UniversalMention, FriendTags (own storage, own settings page), Ghosted (uses `ctx.serverList`), Experiments (switched off in her settings: it can put an account at risk; only the patches that match the build were kept). - **2026-10-29 · BetterInvites brought, and what was found about ChannelTabs and the patcher (Neversleeper).** BetterInvites is in (off by default, starts at `init`): inviter line with avatar, a live countdown to the end of the invite, and a click on the server name that joins as a visitor for discoverable servers. Its patches were written again from the live code of Discord's invite card (build 653945), not from the original: the card module is found by `.t.xdCLeM` and the name module by a regex on its code. Rules learned that apply to every plugin: a patch is used up by the first module that matches its `find`, so a loose `find` can hide the module that was meant (give a precise find, a regex is allowed); a component that lives in a module registered before `webpackReady` needs `startAt: "init"`; `ctx.addStyle` does nothing at `init`, add the style when the component is first drawn. ChannelTabs: the bar did not show because Discord's app is a CSS grid with no free row; it now floats over a strip of its own and the main part gets padding of the same height, and it starts again every 0.5 s until the account is known. Ghosted: Discord only holds the messages of chats that were opened, so the last message of the other chats is asked once (limit 1, one chat every 0.4 s). Experiments: the widget experiment is `2026-07-personal-widget` and unlocks only the editor; the server rejects widget uploads (401) for accounts it has not opened it to.
